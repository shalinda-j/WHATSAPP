## 2024-05-24 - Webhook Secret Validation Timing Attacks
**Vulnerability:** String comparison operators (`===` or `!==`) were used to compare incoming webhook signature headers with expected application secrets in `src/server/routes/webhooks.ts`. This allows an attacker to perform timing attacks by measuring response times to guess the secret character by character.
**Learning:** Even simple string comparisons for API keys or secrets are vulnerable in Node.js. `crypto.timingSafeEqual` is required, but it throws an error if buffer lengths mismatch, creating a secondary DoS vulnerability if not handled.
**Prevention:** Always use `crypto.timingSafeEqual` with SHA-256 hashes of both strings when comparing secrets. Hashing first guarantees the buffers are identical in length (32 bytes), safely preventing both timing attacks and length-mismatch errors. Ensure explicit type checks (e.g., `typeof token === 'string'`) exist before hashing user input to prevent unhandled type errors.
